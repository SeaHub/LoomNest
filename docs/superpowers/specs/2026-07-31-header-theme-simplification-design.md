# LoomNest 页头导航与主题简化设计

## 目标

隐藏页头右侧的 `Works` 导航，仅保留正文作品区的 `Works` 标题。主题控件在界面上只呈现深色与浅色，不展示系统模式；在用户未手动选择主题时，页面仍持续跟随系统配色。

## 页头导航

从 `.site-nav` 中移除指向 `#works` 的 `Works` 链接。品牌、分类筛选、主题按钮、正文锚点和跳过链接保持不变。

页头桌面端继续使用现有三列网格；中间导航区域只承载分类筛选，并填满可用宽度。移动端移除原先为 `Works` 链接预留的第一列，使分类筛选占据第二行全部宽度。不得通过仅设置视觉隐藏来保留一个可聚焦链接。

正文中的 `ARCHIVE / 01—∞`、`#works-heading` 与 `Works` 标题不变。

## 主题状态

主题在界面上只有 `light` 和 `dark` 两种可选择状态。内部用“本地没有明确选择”表示自动跟随系统，不增加第三个可见主题选项。

- 当 `localStorage['loomnest-theme']` 为 `light` 或 `dark` 时，使用并保持该明确选择，不响应系统配色变化。
- 当存储值缺失、为旧值 `system` 或为其他无效值时，不把默认值写入本地存储；页面读取 `prefers-color-scheme: dark`，并在系统配色变化时实时更新。
- 用户点击主题按钮时，切换到当前实际主题的相反主题，并将新的 `light` 或 `dark` 写入本地存储。从这次操作开始停止跟随系统。
- 若本地存储不可访问，当前会话仍可完成手动切换；写入失败不阻断交互。

主题按钮只显示当前实际主题和下一主题，例如 `深色 · 浅色` 或 `浅色 · 深色`。无论处于自动跟随还是明确选择状态，按钮文本和无障碍名称均不得出现“系统”或“跟随系统”。

## 系统主题监听

保留 `prefers-color-scheme: dark` 的媒体查询监听，因为自动跟随仍依赖它。监听回调始终更新系统主题状态；只有本地没有明确选择时，这个状态才影响实际主题。

组件卸载时继续移除媒体查询监听，避免遗留事件处理器。

## 数据与兼容性

`system` 仅作为历史存储值兼容，不再作为可选主题写回。现有 `light` 和 `dark` 用户偏好保持不变。

主题更新继续同步：

- `document.documentElement.dataset.theme`；
- `<meta name="theme-color">`；
- CSS 的 `color-scheme`。

不修改作品数据、筛选、展开交互、动画或静态原型目录。

## 测试与验收

自动化测试应先失败再由实现修复，并覆盖：

- 未明确选择时根据系统偏好解析为深色或浅色；
- 系统偏好变化只影响未明确选择的状态；
- 旧值 `system` 和无效值等同于未明确选择；
- 用户点击后得到相反的明确主题，并只持久化 `light` 或 `dark`；
- 页头模板不再包含右侧 `Works` 导航；
- 主题控件不呈现“系统”文字。

完成后运行完整测试与生产构建，并在桌面和移动宽度检查页头：分类筛选不与主题按钮重叠、无多余空列、页面没有横向溢出。

## 方案取舍

采用“可见两态、未选择时隐式自动跟随”的方案。相比完全移除系统监听，它满足默认动态跟随；相比保留可见的三态切换，它满足界面仅支持深色和浅色的要求；相比改成两个并排按钮，它保留当前紧凑的胶囊按钮布局。
